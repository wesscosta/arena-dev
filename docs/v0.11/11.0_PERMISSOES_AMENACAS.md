# v0.11 / 11.0 — Permissões, fronteiras de confiança e ameaças

**Estado:** auditoria de código v0.10 e política proposta para 11.1. Não apresenta endpoints futuros como implementados. **Escopo de implantação:** self-hosted, um professor por instância; não presume SaaS/multi-tenancy.

## Evidência real na baseline

- `SecurityConfig.java` permite sem login de professor: `/api/join/**`, `/api/learn/**`, `/api/projector/**` e `/ws/**`; `/api/**` demais exige `ROLE_TEACHER`. Os serviços de aluno e canais WS precisam aplicar suas próprias verificações de código/token. CSRF permanece obrigatório para mutações do professor (`/api/join/**` e `/api/learn/**` são exceções legadas).
- `ProjectorController.get("/{code}")` resolve código de sessão e responde um `PublicRuntimeSnapshot` por `SessionRuntimeSnapshotService.projector`. Um **código conhecido funciona como credencial de acesso à superfície pública da sessão**, não como autorização para Biblioteca privada.
- `SessionSocketHandler` autentica conexão do projetor com `AUTH_PROJECTOR`; participante com token, docente pelo principal HTTP. As transmissões de `LIVE_STAGE_STATE` possuem projeções diferentes para professor/participante/projetor via `LiveStageService.project`.
- **Via de desvio a prevenir em 11.1:** o endpoint genérico `PUT /api/sessions/{sessionId}/stage` usa `ActivateCommand`; quando o enum ganhar `MATERIAL`, bloquear explicitamente este modo nessa rota e exigir publicação transacional via serviço dedicado.
- `ArenaResourcePlacementService.link` exige sessão ativa, material global publicado (`libraryVisible`), não arquivado e sem `classroom` privada. `get` retorna id, título, revisão e disponibilidade. **Link não publica conteúdo ao projetor.**
- `LearningResourceService` mantém revisão mutável, hashes/proveniência e o conteúdo corrente. Há snapshot em `JourneyStage`, mas **não foi identificada tabela genérica de versões imutáveis de LearningResource** para projeção histórica.
- Limite importante: `LearningResourceService.getLibrary` pode retornar recurso arquivado conforme condição de leitura atual. **Nunca usar essa leitura geral como contrato de publicação pública.** Política de publicação deve consultar explicitamente visibilidade, arquivamento, escopo e sessão ativa.
- Contratos atuais não representam versão monotônica de palco (há `activatedAt`), nem modo `MATERIAL`. Não considerar mensagens WebSocket fonte durável ou ordenadora por si.

## Matriz de autorização: efetivo atual versus obrigação futura

| Ação | Docente autenticado | Participante com token | Projetor com código | Anônimo sem código |
| --- | --- | --- | --- | --- |
| Listar/editar Biblioteca privada | Permitido no modelo docente único | Negado | Negado | Negado |
| Vincular material à sessão | Permitido via API docente | Negado | Negado | Negado |
| Consultar estado público de sessão | Pela API docente | Somente visão filtrada | Somente visão filtrada | Negado |
| Publicar material no palco (11.1) | **Somente docente**, CSRF + sessão ativa + material elegível | Negado | Negado | Negado |
| Navegar seção publicada (11.3) | **Somente docente**, controle de versão | Negado | Negado | Negado |
| Retirar publicação (11.1) | **Somente docente**; revogação também em encerramento/desvinculação | Negado | Negado | Negado |
| Ler payload da publicação atual (11.1) | Via API docente | **Negado no MVP** | Permitido por código válido, apenas modo MATERIAL e sessão ativa | Negado |
| Ler versões anteriores / listagem / metadados privados | Negado no endpoint público | Negado | Negado | Negado |

**Escolha conservadora:** o participante não recebe o Markdown apenas por possuir token de entrada na sessão. Se a equipe decidir permitir material ao participante, exigir ADR e UX específicos para essa audiência, sem piggyback no endpoint de projetor.

## Ameaças e controles indispensáveis

| ID | Falha | Mitigação contratual e teste negativo |
| --- | --- | --- |
| SEC-01 | Código compartilhado permite enumerar acervo | Endpoint público **somente da publicação corrente**, sem ids arbitrários, catálogo, busca, origem, autor, caminho ou referência externa |
| SEC-02 | Material muda após professor publicar | Captura **imutável de conteúdo e outline no ato da publicação** com `sha256`, `resourceRevision` e `publicationId`; navegação usa esse snapshot |
| SEC-03 | Arquivamento/desvinculação/encerramento deixa material visível | Revogação transacional; respostas públicas sem conteúdo em revogações e leitura revalida sessão, publicação e recurso elegível |
| SEC-04 | Usuário injeta HTML, scripts, iframe, data-URL ou imagem remota com token | Renderer GFM restrito, HTML bruto não interpretado, esquemas URL permitidos, links seguros; imagens somente com política explícita de origem e sem credenciais |
| SEC-05 | Duas janelas/professores enviam estado obsoleto | Sequência monotônica por sessão + `expectedVersion`/`409`, travamento transacional do estado; idempotência em mutação conforme política |
| SEC-06 | GET/WS vazam dados privados ou pessoais | Diferenciar projeções `TEACHER`/`PROJECTOR`/`PARTICIPANT`; testes que rejeitam campos de Biblioteca e dados de estudante |
| SEC-07 | Captura pública em caches/PWA/logs | `Cache-Control: no-store` para conteúdo público, não incluir corpo em logs/WS, sem cache do service worker; política de expiração/revogação explícita |
| SEC-08 | Sessão de código inválido ainda revela existência de recurso | 404/410 neutro; não refletir ids ou título em erros; revisar limitação de tentativas e logs mínimos |
| SEC-09 | Conteúdo gigante afeta memória/tempo de resposta | Limites medidos de tamanho/blocos/tempo antes de admitir publicação; fallback seguro, sem payload completo em cada troca de seção |
| SEC-10 | Token de aluno confundido com autorização docente | Mutação sob `ROLE_TEACHER` + CSRF; integração testada como participante, anônimo e código de projetor |

## Invariantes de publicação

1. `Vincular` nunca implica `publicar`; selecionar/abrir modal nunca altera palco ou pontuação.
2. `PUBLICATION_ACTIVE` implica sessão ativa, fonte elegível e um snapshot imutável já persistido; o id da publicação aponta para exatamente um recurso/revisão.
3. Mudar de modo não altera rodadas, tentativas, ScoreEvent, JourneyProgress, Mastery ou presenças.
4. Qualquer revogação tem precedência sobre evento tardio da mesma publicação. Recarregar ou reconectar nunca reabre conteúdo retirado.
5. O usuário que conhece o código consegue **ver** somente o que o professor explicitamente publicou na tela compartilhável; código não concede acesso à Biblioteca.
6. Apenas a próxima fase implementa esses controles: a baseline v0.10 **não** possui publicação de material e não é considerada vulnerável por não expor essa funcionalidade ainda.

## Testes de segurança obrigatórios em 11.1/11.3

- 401/403 para publicação/navegação sem autenticação docente ou sem CSRF; token de aluno e código do projetor não bastam.
- 404/409 para recurso privado, arquivado, de turma ou desconhecido; nenhum conteúdo nos erros.
- Code A ≠ code B; sessão B não vê material da A; encerramento, desvinculação e arquivamento revogam.
- Inspecionar JSON público: não há `sourceUrl`, `sourceReference`, corpo de material privado, emails, IDs de alunos, histórico de edição.
- Conteúdo malicioso (HTML, links `javascript:`, imagens remotas não autorizadas, Markdown com `<aside>`) permanece inerte; testes automatizados e auditoria de CSP.
- Conteúdo imutável após edição e refresh; cenários de comandos concorrentes, eventos fora de ordem, GET após revogação, PWA offline.
