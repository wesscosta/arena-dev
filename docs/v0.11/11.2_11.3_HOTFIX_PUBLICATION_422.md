# Correção — API 422 ao apresentar material com exemplos HTML/JavaScript

**Data:** 10/10/2026. **Categoria:** correção do fluxo 11.2/11.3, sem ampliação de escopo ou mudança de contrato público.

## Evidência do problema

- No modal **Biblioteca nesta aula**, ao clicar em **Apresentar no projetor**, materiais didáticos de Django retornavam HTTP 422 com mensagem genérica.
- Consulta somente de leitura ao PostgreSQL mostrou três materiais relacionados a “Controle de Estoque com Django” com aproximadamente 99 mil caracteres cada — abaixo do limite de 120 mil.
- Os documentos contêm tags HTML `<img>` e `<script>` **dentro de blocos de código Markdown** (exemplos de templates Django e JavaScript).
- A validação anterior buscava essas strings no corpo completo, mesmo em exemplos literais, e abortava a publicação.

## Correção

- Scanner sensível à estrutura do Markdown: blocos cercados por crases ou tils, trechos de código inline e código indentado são tratados como exemplos inertes.
- HTML ativo, scripts, protocolos `javascript:`/`data:` e imagens incorporadas **fora** de blocos de código continuam impedidos pela defesa no backend.
- `PLAIN_TEXT` permanece seguro: renderizado como texto escapado, sem interpretação de HTML.
- Leitor público mantém `skipHtml`, sem `rehypeRaw`; imagens, links externos clicáveis e formulários continuam indisponíveis.
- Erros legítimos de formato, tamanho, conteúdo vazio e HTML ativo retornam JSON com explicação ao professor, em vez de somente “Falha na API (422)”.
- Nenhuma alteração ao material original, aos snapshots já publicados, à autorização, CSRF, revogação, estado de sessão ou às migrações.

## Validação

- Testes de unidade cobrem cercas de código `backticks` e `~~~`, código indentado/inline, rejeições fora dos blocos e `PLAIN_TEXT`.
- Integração com PostgreSQL comprova publicação de material Django sintético de aproximadamente 99 mil caracteres, sem criar código executável no projetor; teste HTTP valida resposta 422 explicativa sem exposição do conteúdo.
- **Validação de regressão diretamente sobre o texto real, somente leitura:** `chars=99200 unsafe=false`, sem exportar ou alterar a fonte.
- E2E Chromium foi ampliado para publicar Markdown com exemplos `<script>` e `<img>` cercados, exibindo-os como texto nos blocos de código e sem nós `script`/`img` no DOM.
- Gate exigido antes de merge: backend, frontend e Compose/Playwright aprovados no mesmo SHA.

**Nota operacional:** corrigir o GitHub não altera automaticamente o backend em execução. A instância atual usa Flyway V57; qualquer atualização local será registrada separadamente e exigirá controle do ciclo de implantação.
